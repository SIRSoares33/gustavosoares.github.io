Visão geral

Infraestrutura real e laboratório técnico

Uma base para o ecossistema pessoal

O Logos está sendo construído para hospedar e organizar meus serviços, APIs, automações, bancos, arquivos, ferramentas administrativas e projetos experimentais. O objetivo de longo prazo é concentrar tudo o que for meu em uma infraestrutura documentada, persistente, recuperável e expansível.

Estratégia VM primeiro

A primeira fase utiliza Ubuntu Server em uma máquina virtual no VirtualBox. Assim, consigo validar rede, acesso remoto, containers, persistência e backup antes de uma futura migração para hardware dedicado ou bare metal, sem tratar decisões ainda experimentais como definitivas.

Arquitetura atual

Implantado

Logos

O host Ubuntu Server que abriga o ecossistema. SSH e Tailscale iniciam com o sistema, e o Tailscale permanece independente do Docker para preservar o acesso remoto ao host. O Wake-on-LAN permite sua inicialização remota.

Implantado

Starlink

Rede bridge compartilhada que permite comunicação privada entre projetos Compose separados usando o DNS interno do Docker.

Implantado

Sophia

Instância PostgreSQL central e persistente. Cada aplicação recebe seu próprio banco e usuário técnico; administração e aplicações usam credenciais separadas.

Implantado

Sophia's Window

Interface pgAdmin persistente para administração visual da Sophia, conectada internamente pela Starlink e mantida fora da exposição pública.

Implantado

Hermes

Serviço n8n com volume persistente, banco e usuário próprios na Sophia e chave de criptografia preservada. Recebe webhooks e callbacks OAuth por HTTPS através do Tailscale Funnel.

Planejado

Janus

Futura camada de gateway para separar a entrada pública necessária para webhooks das interfaces administrativas privadas.

Armazenamento por responsabilidade

O SSD concentra sistema, Docker, aplicações e bancos ativos. O HD recebe arquivos pessoais e cópias locais de backup. Configurações, persistência, dados de negócio, dumps e itens recriáveis são tratados separadamente para permitir reconstruções seletivas.

Organização operacional

Definições de containers, volumes, secrets, scripts, storage e backups possuem responsabilidades separadas. Os serviços usam a política restart: unless-stopped, enquanto a documentação necessária para reconstrução é mantida externamente para não depender da integridade da VM.

Operação e recuperação

Acesso controlado e dados recuperáveis

A segurança é aplicada por redução de exposição, separação de credenciais, permissões adequadas e uma estratégia de backup que continua amadurecendo.

01

Segurança operacional

  • SSH acessível pela LAN ou pelo Tailscale, sem publicação direta na internet.
  • PostgreSQL, painéis administrativos e armazenamento permanecem privados.
  • Secrets possuem acesso restrito e as aplicações usam credenciais de banco isoladas.
  • O Hermes está acessível pela internet através do Tailscale Funnel para receber webhooks e callbacks OAuth; a URL pública não é divulgada.
  • O Janus permanece planejado para separar as rotas públicas do Hermes da superfície administrativa.
02

Backup criptografado

  • Dumps consistentes do PostgreSQL com preservação de roles e permissões.
  • O diretório ativo do PostgreSQL fica fora da cópia genérica; a recuperação do banco parte dos dumps consistentes.
  • Snapshots criptografados e deduplicados pelo Restic.
  • Transporte remoto por rclone para um repositório no Google Drive.
  • Configurações, volumes importantes, scripts, storage e secrets entram na seleção de recuperação.
