Visão geral

O problema

Meus clientes de marketing precisam manter publicações regulares no Instagram, Facebook e LinkedIn. Criar arte, legenda, hashtags, solicitar aprovação e postar toda semana formava uma sequência manual repetitiva, sujeita a atrasos e perda de contexto.

A solução

Criei o AutoPost IA para centralizar esse processo em um workflow agendado. Em produção, ele usa a OpenAI para criar o conteúdo a partir do briefing semanal, espera a decisão do cliente, publica somente após a aprovação e registra o resultado.

01

Disparo agendado

O n8n inicia o workflow nos dias configurados para cada cliente e carrega o tema ou briefing definido para a semana.

02

Geração com IA

A API da OpenAI cria a arte, a legenda e as hashtags relevantes de acordo com o briefing e o contexto preparado para cada cliente.

OpenAI • artes • legendas • hashtags

03

Aprovação assíncrona

A prévia da arte e do texto é enviada por WhatsApp ou email. O recurso Wait for Webhook mantém a execução em espera até o cliente aprovar ou solicitar um ajuste.

Aprovação • WhatsApp e email

04

Publicação controlada

Com a aprovação registrada, o workflow envia o conteúdo para Instagram e Facebook pela Meta Graph API e para o LinkedIn pela API oficial.

05

Ciclo de ajuste

Quando o conteúdo é rejeitado, o feedback retorna ao fluxo para regeneração orientada ou edição manual antes de uma nova solicitação de aprovação.

06

Log e notificação

Cada execução registra sucesso ou falha e notifica a equipe quando a publicação é concluída, formando um histórico auditável.

Infraestrutura

Dois públicos, duas rotas de acesso

O n8n roda em Docker no meu servidor on-premise. Eu administro os workflows pela rede privada Tailscale; meus clientes aprovam posts por um webhook específico publicado pelo Cloudflare Tunnel, sem entrar na minha rede.

Não é uma única camada de acesso.

Administração = somente Gustavo via Tailscale. Aprovação = somente o webhook necessário via Cloudflare Tunnel. O cliente não instala VPN e não recebe acesso ao painel ou a qualquer outra parte do servidor.

Acesso administrativo • privado

Gustavo → Tailscale → Painel do n8n

O Tailscale, uma VPN mesh baseada em WireGuard, mantém a interface administrativa fora da internet pública. Somente meus dispositivos autenticados na tailnet conseguem acessar, criar ou editar workflows; nenhuma porta administrativa fica exposta.

Acesso do cliente • público restrito

Cliente • link normal → Cloudflare Tunnel → Webhook de aprovação

O cliente abre normalmente o link recebido por WhatsApp ou email, sem instalar VPN. Um container cloudflared no mesmo Docker Compose do n8n cria uma conexão de saída até a Cloudflare e publica somente a rota do webhook, sem abrir portas no roteador nem expor o IP da rede doméstica.

01

Menor superfície de exposição

Somente o endpoint que precisa receber a decisão do cliente fica público; o painel e os serviços internos permanecem invisíveis.

02

Cada público usa o acesso adequado

Eu uso a VPN para administrar; o cliente usa um link comum para aprovar. Ele não precisa instalar software nem entrar na minha rede.

03

Túnel outbound, sem abrir portas

O cloudflared inicia a conexão de dentro para fora. Não há port forwarding nem divulgação do IP da rede doméstica.
